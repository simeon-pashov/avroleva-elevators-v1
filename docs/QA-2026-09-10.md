## 3. Security quick-check

- `/s/:token`: unknown token 404; 60 requests / minute per IP, the 61st → 429; revoked → 404
  (expired → 404 is covered by `step9b.test.ts`, there is no API path to mint an expired link).
- `/pay/demo/:token`: 404 outside demoMode (toggled through the admin API), unknown token 404.
- `/downloads/tech.apk`: the file path is a constant (`resolve(DATA_DIR, 'releases', 'tech.apk')`);
  raw (un-normalised) requests `/downloads/../.env`, `/downloads/tech.apk/../../.env`,
  `/downloads/%2e%2e/%2e%2e/package.json`, `/downloads/..%2f..%2f.env`, `tech.apk%00.txt` → 404.
  (Node's `fetch` normalises `..` client-side to `/.env`, which the SPA fallback answers with
  `index.html` — not the file.)
- `/geo/search`: owner/office only (technician 403), `q` < 2 chars → 400, upstream serialised at
  1 req/s with a 10-minute cache, API limiter 600/min.
- Cross-tenant: the isolation suites (`step7`–`step11`) plus the second-company flow above.
- Login limiter (20 / 15 min per IP) tripped during the repeated script runs — as designed.
- `git ls-files | grep -iE "(^|/)\.env"` → `.env.example`, `.env.production.example` only;
  `keystore.properties` and `*.jks` untracked (`apps/tech/android/keystore.properties.example`
  is the template).

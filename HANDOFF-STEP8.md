# Avroleva Elevators — Handoff after step 8 (repair jobs and quotes, address search)

Date: 2026-09-10. Read `HANDOFF-STEP7.md` (billing, the `issueInvoice` entry point this step uses), `docs/adr/0001-billing-jobs-payments.md` and `ARCHITECTURE.md` §1–§3 first. Vocabulary rule kept: jobs, quotes, approval, warranty, invoices — nothing regulator-facing. Approval stages and the state machine are DATA (system defaults + tenant override), like dunning stages.

## 0. Task A (quick fixes, first commit)

- `settings.billing.showPaymentOnPublicPage` defaults to **false**: whoever scans the cabin QR does not see the building's arrears unless the firm opts in (billing settings page; step 7 test now sets it explicitly).
- `invoice.contractId` is nullable (migration `20260910000000_invoice_contract_nullable`); `(tenantId, contractId, periodStart)` stays unique (NULLs never collide). `InvoiceDto` carries `sourceId` and `jobId` (= `sourceId` when `sourceType = 'job'`); customer names for contract-less invoices resolve by customer.
- `billing.issueInvoice({sourceType:'job', sourceId, buildingId, customerId, lines, issuedAt?, dueAt?})` — numbering + payer reference in one transaction, VAT rounded once, `InvoiceIssued`; `billing.listForSource(ctx, 'job', id)` for the job detail. The jobs module reaches both only through its `InvoiceIssuer` port.

## 3. Schema

`job` (id, tenantId, elevatorId, buildingId, customerId?, kind `repair|modernisation|other`, title, description?, originType `visit|callback|defect|office`, originId?, status TEXT (stage code), quoteVersion, netCents, vatCents, totalCents, vatRatePercent (snapshot), approvalEvidence JSONB?, quoteSentAt?, quoteValidUntil?, approvedAt?, scheduledAt?, assignedUserIds UUID[], startedAt?, completedAt?, visitId?, invoiceId?, invoicedCents, warrantyUntil?, rejectedReason?, cancelledReason?, notes?, createdByUserId?, timestamps); `job_line` (jobId, quoteVersion, kind `labour|part|other`, description, qty FLOAT, unitCents, totalCents, partRef?, position); `job_event` (jobId, type, fromStatus?, toStatus?, at, receivedAt, source `office|app|public`, byUserId?, data JSONB — append-only); `job_stage` (tenantId?, code, labelBg, labelEn, position, isTerminal, allowedNext TEXT[], requiresEvidence, active; unique (tenantId, code)). FKs only to identity tables (tenant, elevator, building); origin / visit / invoice are id references without FKs (ARCHITECTURE §1.1 rule 4). ## 6. Known gaps

- Nominatim: results are *biased* to the tenant's area, not bounded — "ж.к. Дружба 1 бл. 45" without a city can rank a block in another town first; adding the city to the query fixes it. A second, bounded request as a fallback is one line in the adapter. Sofia OSM data is uneven for streets ("ул. Раковски 12" found nothing); the pin can always be placed by hand.
- No PDF: the quote is a print page / HTML attachment like the invoice.
- The reminder is in-app only (office); a Viber/e-mail nudge to the building would be a rule + template.
- Photos of the approval evidence (`attachmentId`) are accepted by the API but the office form does not upload one yet.
- The quote e-mail goes to an address typed in the dialog (defaults are not prefilled from the building contact; the statement dialog does that and can be copied).
- Job invoices carry the elevator on every line (InvoiceLineDto keeps `elevatorId`); the statement / EPC work unchanged.
- `job_line.qty` is a float (3 decimals kept); totals are rounded per line.
- Demo: back-dated `createdAt`/`quoteSentAt` only; events keep the generation time.
- `.claude/launch.json` (untracked) is a local browser-pane convenience; `npm run dev` started from a shell is what the verification used.

**Building magic-link statement page**: `billing.statement(ctx, buildingId, window)` + `renderStatementHtml` exist; add a `building_link` table (token, buildingId, expiresAt) in registry, a public route `/s/:token` (like `/p/:token`) rendering the statement + open invoices + the EPC block, honouring `showPaymentOnPublicPage`-style opt-in per link, and "send link" from the building page through `notifications.sendEmail` / Viber. Quotes could ride the same link: `GET /s/:token/quote/:jobId` with an "approve" button that calls `jobs.transition(approved, {kind: 'email'|'link', by, at})` — the evidence kind list would gain `link`.
